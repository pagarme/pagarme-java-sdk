# Agent Instructions

Guidance for AI coding agents (GitHub Copilot, Claude Code, and others reading `AGENTS.md`) working in this repository.

## What this is

A fork of Pagar.me's official Java SDK (`me.pagar.api`, Pagar.me Core API v5 at `https://api.pagar.me/core/v5`). Nearly all code is **generated by APIMatic** (see the header on each file) and the upstream repo is regenerated wholesale via "Automated commit message" PRs. Local changes in this fork are hand-made patches on top of generated code, so keep them small and isolated so they survive merging a new upstream regeneration.

Fork-specific changes so far:
- `ApiHelper.getBase64EncodedCredentials` overrides the `CoreHelper` version to treat null username/password as `""`. Pagar.me secret keys are used as the Basic-auth username with an empty password, which the upstream helper rejected. `BasicAuthManager` depends on this override.
- `pom.xml` adds `maven-release-plugin` (tags `v<version>`, `pushChanges=false`) and `distributionManagement` pointing to the private Nexus (`nexus-abm`, `https://nexus.abmpecas.com/...`).

## Build

Java 8+ (enforced by `maven-enforcer-plugin`). The project has no tests (there is no `src/test`).

```
mvn compile
mvn install -Dmaven.test.skip=true                              # install to local repo (from README)
mvn deploy                                                      # publish to nexus-abm (needs credentials in ~/.m2/settings.xml)
mvn release:prepare release:perform                             # versioned release; tags are not pushed automatically
```

`versions-maven-plugin` references `version-rules.xml`, which isn't in the repo, so `versions:*` goals will fail unless you create that file.

Dependencies come from `io.apimatic` (`core`, `core-interfaces`, `okhttp-client-adapter`) and are declared with version *ranges*, so builds can pick up newer patch versions.

## Architecture

- `PagarmeApiSDKClient` is the entry point. It is built with `PagarmeApiSDKClient.Builder` (basic-auth credentials, http client config, `serviceRefererName`). It owns a `GlobalConfiguration` (from apimatic-core), registers the `"httpBasic"` auth manager, and creates one controller per API area in its constructor (`getChargesController()`, `getOrdersController()`, ...).
- `controllers/`: each API area is an interface (`ChargesController`) plus a generated `Default*Controller` implementation that extends `BaseController`. Every endpoint has a sync method, an `...Async` method returning `CompletableFuture`, and a private `prepare...Request` that builds an apimatic `ApiCall` declaratively (path, template, query and header params, serializer, deserializer). `BaseController.GLOBAL_ERROR_CASES` maps HTTP 400/401/404/412/422/500 to `ErrorException`.
- `models/` holds about 240 Jackson-annotated request and response POJOs with builders (`Create*Request`, `Update*Request`, `Get*Response`, `List*Response`). Polymorphic and nullable fields use apimatic's `OptionalNullable`.
- `http/`, `exceptions/` and `utilities/` are thin wrappers or adapters over apimatic-core types. `ApiHelper` (extends `CoreHelper`) does JSON (de)serialization.
- `doc/` contains generated Markdown reference docs for the client, controllers and models. The README links to the upstream GitHub copies of these docs.
